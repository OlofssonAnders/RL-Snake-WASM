Reinforcement Learning with Snake

In this article I present my journey to beating snake using Reinforcement Learning! The game has simple rules and the set of possible actions at any given moment is small, the game is simple enough to be implememted in a few lines of code and is therefore a perfect candidate for testing out reinforcement learning models. It is also surprisingly difficult to beat using purely heuristic approaches, where the agent is programmed with a set of rules to follow.

The game is rendered using Macroquad which is a simple and easy to use game engine for rust. The game logic and visual design is a direct copy of one of their examples listed on their website.

I started by implementing a simple agent that chose actions randomly just to iron out any issues with the game to agent-interface Unsurprisingly, the random agent was rarely able to score any points. Following this I implemented the "heuristic" agent to set a baseline to compare against. I then implemented progressively more complex agents in the rust programming language. All code is available on my github page. The demos were compiled to WebAssembly, as macroquad provides excellent support for this. This is significantly faster than javascript and allows my demo to run more smoothly.

The agents presented below are:

  1. Random Agent
  2. Heuristic Agent (Following predefined rules)
  3. Q-Learning Agent
  4. User Input (If you want to try it yourself)

Random Agent

At each time step, this agent chooses one of the five possible actions (up, down, left, right or wait) at random.

Heuristic Agent

The heuristic agent uses hand-written rules. I's programmed to move directly towards food and avoid immediate collisions with the border. Defining rules to avoid situations where the snake collides with itself or ensnares itself was difficult, and I eventually gave up on the idea as it happens to exemplify the limitations of heuristical approaches well. In addition to poor generalization, rules quickly become complex and dificult to integrate into the model.

As can be seen in the demo, the heuristic agent is able to survive for a while, but eventually it runs into itself. It will do this over and over again as the implementation does not have any kind of learning. On average, the heuristic agent will score higher than the random agent, but it is still far from optimal. Heuristic agent implementation details

Q-Learning

Q-learning is an algorithm that learns which actions are most valuable in different states, allowing the agent to approximate an optimal policy (playing strategy). Reward in this context is a numerical value that the agent receives for each action it takes. Naturally, it is important to specify what constitutes a good reward. In this context, keeping the snake alive should be rewarding. It should also be rewarding to collect food. After a bit of experimentation, the reward function (returning a reward given an action and state) for the snake game was defined as follows:

  • Colliding and dying: -1.0
  • Collecting food: 50.0
  • Reducing distance to food: 10.0
  • Doing nothing of the above: -0.001 (This was added to prevent the snake from circling indefinitely)

The algorithm works by storing and updating a value for each state-action pair. This value (Q-value) estimates the expected cumulative future reward from taking that action in that state and behaving optimally thereafter. These values are constantly updated as the agent explores the environment and receives feedback in the form of rewards.

The states, in this context, do not capture the entirety of the information available from the game. They are only simplified portions. The number of unique states to consider given all the available information, even in a small game like Snake, would become too large to handle. Therefore the number of states that the agent is exposed to is reduced by considering only the most useful pieces of information.

Similar to how it is important to define a good reward function, it is also important to define a good state representation. What should the agent "see" in order to make good decisions while not overwhelming it with too much information? The state representation I used is the following:

  • There is a wall or body segment (aka obstacle) immediately above the head, below, to the left, or to the right
  • The food is above, below or on the same row as the head
  • The food is to the left, right or on the same column as the head

The procedure that computes how the state-action pairs should be updated for each step, as the agent is traversing the environment, is not overly complicated, it only needs the current state, the action taken, the immediate reward, and what the next state is going to be (along with parameters for exploration rate etc.) see Q-Learning algorithm. This agent, playing snake below, was trained by playing the game 30 000 times. In the demo, the exploration rate is set to 0, meaning that the agent will always choose the action that is deemed to yield the highest reward. Q-Learning implementation details
